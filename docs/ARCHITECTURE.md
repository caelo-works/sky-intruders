# Sky Intruders — architecture

*Who crossed your photo last night?* Sky Intruders scans a night's light frames for
trails, identifies them (satellite via TLE cross-match, meteor via active-shower
heuristics, slow movers as asteroid candidates) and renders a night-log report with
fun stats and a Reddit-ready post.

**100% PJSR — no native helper.** Networking uses PixInsight's `NetworkTransfer`
(probed working under `#engine v8`, see `tests/probe-networktransfer.js`); orbital
mechanics uses a vendored [satellite.js](https://github.com/shashwatak/satellite-js)
5.0.0 (SGP4, MIT) plus our own matching engine. An earlier development stage used a
Go sidecar for these two jobs; it was removed once `NetworkTransfer` was validated,
and it survives in git history as the **reference implementation**: the fixtures
under `tests/fixtures/match/` were generated by that Go engine (Vallado-verified
SGP4, 24 tests under `-race`) and the JS engine must replay them within tolerance.

## Pipeline

1. User picks light frames (or a directory). With 3+ frames of one field the
   set goes through **registered-difference analysis** (below); otherwise each
   frame is analyzed independently.
2. `SITleNet.fetchTle` — CelesTrak GP catalog through NetworkTransfer, disk cache
   (default max-age 12 h), base URL overridable (mirrors).
3. `SISatMatch.match` — for each frame's exposure window, propagate the catalog,
   find satellites crossing the FOV, match them to detected trails by angular
   separation + orientation + rate. The sunlit test runs at every sample of
   the crossing: a satellite that enters or leaves the Earth's shadow inside
   the field is matched on its lit sub-path and the transition instant is
   reported; only a crossing lit at no sample is flagged eclipsed. A FOV
   without a known rotation (frame not plate-solved) is tested as its
   bounding circle.
4. Frames without WCS: `SISatMatch.fitOrientation` recovers the field rotation
   and mirror parity by brute force against the sunlit crossings (center and
   plate scale come from the pointing headers; the fit also corrects the
   center by the median offset of its matched pairs). The winning synthetic
   TAN gives every trail sky coordinates; `assignTrails` then names them.
5. Airplane heuristic: 3+ near-parallel segments in one frame (wing lights +
   strobes) collapse into a single "plane" event, excluded from matching.
6. Classification of leftovers (JS): unmatched satellite-like trail →
   "unidentified satellite"; brightness-variable / interior trail aligned with an
   active shower radiant → "probable <shower> meteor"; compact sources drifting
   coherently across ≥3 frames (real WCS required — fitted astrometry is too
   coarse and dither shifts sensor artifacts coherently) → asteroid candidate.
   Tracks sharing one velocity are tested as a registration-drift family, not
   vetoed outright (asteroids near opposition co-move): with sensor pixel
   coordinates (single-frame path, blobs carry `x, y` on the frame's own grid)
   a family of ≥3 within max(0.5″/min, 25 % of rate) is dropped only when every
   member stays within 2 px of one sensor position; without them (registered
   path — reference-grid pixels only restate the sky, so the call site strips
   them) the blind rule needs ≥5 tracks within max(0.2″/min, 8 % of rate).
7. Report: chronological night log, stats (counts by operator, Starlink share),
   personal records (persistent history), Markdown export ready for Reddit.
8. Night result image: the registered set max-combined, auto-stretched, every
   trail highlighted and labeled (name + entry time when identified), shown as
   an image window and saved as PNG.

## Trail detection (PJSR)

**Registered-difference path (3+ frames).** Nebulosity defeats any single-frame
line detector — the Veil's filaments are longer, brighter and just as straight
as a faint streak — so the static sky is removed first:

1. `SIRender.registerFramesMapped` — StarAlignment of every frame onto the
   first (keeps the input↔output mapping; falls back per-frame if <3 register).
2. Each registered frame is average-binned (long side ≤ ~1500 px).
3. Static-sky model: per-pixel **median of the non-empty binned values**
   (zero-filled registration borders never vote), valid where ≥3 frames
   overlap, eroded by 3 binned px (binning smear + resampling ring) —
   `SITrailCore.medianStackMasked` / `erodeMask`.
4. Per frame, detection runs on the clamped positive residual
   (`subtractModel`): only transients survive, so the threshold can drop to
   `diffKSigma` (default 3.5) and catch the faint streaks narrowband filters
   leave. Trails land directly in the reference frame's pixel grid.
5. Width veto: residual trails whose full-resolution FWHM exceeds 12 px are
   dropped (cloud bands, stacking artefacts). The FWHM is measured on a
   ±16 px perpendicular profile against the lower of the two outer-annulus
   (|o| ≥ 10 px) backgrounds, median over 8 stations; a profile with no
   half-max crossing inside the window reports `widthPx = null`, which the
   veto also drops. A 6–9 px bright satellite trail is kept.

**Single-frame path (fallback).** As before:

1. Pull pixels in horizontal strips (`getSamples`), average-bin so the long side
   is ≤ ~1500 px.
2. Background/noise on the binned array: median + MAD (robust, hot-pixel immune).
3. Binary map: `sample > median + k·MAD` (k default 5; raised adaptively when
   >8% of pixels exceed it — clouds/gradients).

**Shared line stage (both paths).**

4. Hough transform (θ×ρ accumulator) over above-threshold pixels.
5. **Contiguity validation** (kills star-alignment false positives): a candidate
   line must have a contiguous above-threshold run ≥ minLength with ≥60% fill;
   stars along a chance line are sparse, trails are continuous.
6. Each Hough peak is refined to sub-degree / sub-pixel (θ, ρ) about a point
   on the coarse line before the walk, so an edge-to-edge trail at a
   non-integer angle stays one run instead of 2–3 fragments (1° bins drift
   ~13 px across a 1500-px frame).
7. Accept → record endpoints (scaled back to full-res pixels), erase a corridor
   around the accepted **segment only** (other collinear runs — train
   members, flasher dashes — are re-proposed) and iterate (multi-trail, cap 10).
8. Merge: overlapping near-duplicates (bright and faint pass on one streak)
   keep the longest; collinear fragments within 4 binned px across, 2° in
   direction and a gap ≤ 3 % of the diagonal become one trail with the union
   extent. Farther collinear segments stay separate trails.
9. Photometry at full res (`SITrailCore.measureTrail`): at 64 stations the
   peak within ±1 px of the line minus the local annulus background;
   `meanFluxAdu` is the mean excess, `brightnessVariation` is
   MAD / max(median, 6 × per-sample noise) of the station excesses — sky
   level and gradients cancel, a star crossing the trail only touches its
   own station, and a trail below the full-resolution noise reads ~0.2, under
   the 0.35 flasher/meteor cue (a flasher's alternating dashes read ~0.45+).
   Perpendicular FWHM width as in step 5.

## Matching contracts (internal JS interfaces)

The request/response shapes below are the contract between the entry script and
`SISatMatch.match( request, tleText )` — inherited verbatim from the Go reference
so the committed fixtures stay valid.

Request:

```json
{
  "observer": { "latDeg": 48.85, "lonDeg": 2.35, "altM": 100 },
  "frames": [ {
    "id": "L_0042.fits",
    "startUtc": "2026-07-03T02:13:05Z",
    "exposureSec": 120,
    "fov": { "raDeg": 300.1, "decDeg": 45.2, "widthDeg": 2.1, "heightDeg": 1.4,
             "rotationDeg": 12.3, "hasWcs": true },
    "trails": [ { "index": 0,
      "p1": { "raDeg": 299.8, "decDeg": 44.9 }, "p2": { "raDeg": 300.4, "decDeg": 45.5 },
      "pixLength": 1234, "meanFluxAdu": 5678, "widthPx": 3.2,
      "brightnessVariation": 0.15 } ]
  } ],
  "options": { "stepSec": 1.0, "matchMaxSepDeg": 0.2, "matchMaxAngleDiffDeg": 12 }
}
```

`trails` may be empty or lack sky coords (`"p1": null`) when the frame has no WCS —
crossings are still reported (time-window only) with `"matchedTrailIndex": null`.

Response:

```json
{
  "tle": { "count": 10234, "source": "active" },
  "frames": [ {
    "id": "L_0042.fits",
    "crossings": [ {
      "noradId": 45123, "name": "STARLINK-4512", "intlDes": "2020-001A",
      "entryUtc": "2026-07-03T02:13:41Z", "exitUtc": "2026-07-03T02:13:49Z",
      "path": { "p1": { "raDeg": 299.7, "decDeg": 44.8 },
                "p2": { "raDeg": 300.5, "decDeg": 45.6 } },
      "angularRateDegPerSec": 0.31, "rangeKm": 812, "elevationDeg": 42.5,
      "sunlit": true, "sunlitFraction": 0.62,
      "shadowEntryUtc": "2026-07-03T02:13:46Z", "shadowExitUtc": null,
      "matchedTrailIndex": 0, "matchScore": 0.93,
      "sepDeg": 0.04, "angleDiffDeg": 2.1
    } ]
  } ]
}
```

Matching: a crossing matches a trail when the trail midpoint sits within
`matchMaxSepDeg` *across* the predicted track and within `alongTolDeg` *along*
it (TLE error is dominantly along-track), and the two orientations agree within
`matchMaxAngleDiffDeg` (mod 180°). Orientations are position angles measured at
each segment's **midpoint** (`segmentPaDeg`), not at an endpoint: an endpoint
position angle carries the convergence of meridians (5.9° over a 1° segment at
δ = 80°), which made the gate depend on which end the trail detector labelled
`p1`. Score = 0.4·cross-track + 0.3·angle + 0.2·path-length agreement +
0.1·along-track, conflicts resolved globally by score order.

Sunlit handling: `isSunlit` (cylindrical shadow, no penumbra — ±tens of seconds
near the terminator) is evaluated at **every fine sample** of the crossing.
`sunlitFraction` is the lit share of the in-FOV run (time-weighted); `sunlit`
is `sunlitFraction > 0`. When the flag flips between two samples the instant is
refined by bisection (6 SGP4 calls, ~step/64) and reported as `shadowEntryUtc`
(lit → dark) or `shadowExitUtc` (dark → lit), `null` otherwise. For a
partially lit crossing `path`, `angularRateDegPerSec`, `rangeKm` and
`elevationDeg` describe the **lit sub-path** — the only part that can leave a
streak — while `entryUtc`/`exitUtc` remain the FOV entry and exit. Only
crossings with `sunlit: true` are match candidates (strict and loose assigners,
orientation fit); a crossing lit at no sample keeps its full in-FOV path and is
listed with `"sunlit": false` for the ghost layer. Downstream, a matched
crossing with a transition becomes a satellite event carrying
`shadowEntryUtc`/`shadowExitUtc`, worded in the night log as *"entered Earth's
shadow at HH:MM:SS UT"* / *"left Earth's shadow at HH:MM:SS UT"* (FR: *"entré
dans l'ombre de la Terre à …"* / *"sorti de l'ombre de la Terre à …"*) and on
the composite as *"into shadow HH:MM:SS UT"* / *"out of shadow HH:MM:SS UT"*
(FR: *"entre dans l'ombre …"* / *"sort de l'ombre …"*). Directions are rotated
TEME → J2000 before comparison with the plate-solved WCS.

## Persistent data

- Script parameters: JSON at `~/.caeloworks/sky-intruders/settings.json`
  (full rewrite each save — PJSR append is broken under v8).
- Personal records history: `~/.caeloworks/sky-intruders/history.json`, one entry
  per analyzed night; re-running a night replaces its entry.
- TLE cache: `~/.caeloworks/sky-intruders/tle/<group>.tle` + `<group>.meta.json`.

## Testing

- PJSR pure logic under Node (`tests/run.sh`): strips PI directives, loads the
  vendored satellite.js, unit-tests Stats/FrameMeta/TrailDetect on synthetic data
  (injected lines + noise + fake stars) and replays the Go-generated fixtures
  against SatMatch (`tests/fixtures/match/`).
- `tests/probe-networktransfer.js`: standalone probe for the NetworkTransfer API
  on a real PixInsight install (GUI or headless).
- Two-gate validation on real data: clean console log AND baseline-compared
  report output on a reference night.
